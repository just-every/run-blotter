**Implemented native completion (sx-blotter-c40, 22 Oct):** a contact's language (English or Spanish, default English) is set by the principal or a reviewer on the contact and never by the client; changing only the language keeps the contact's revision, issued links and pending signature requests, while any other edit fences them as before. One shared catalog (`src/i18n`) supplies every client-facing string, so the portal page and its progress, requests, shared files, messages, to-dos, tasks, organizers, signature requests, deliverables and shared logins, the invoice page, the request, organizer-invitation, deliverable, signature, invoice and invoice-reminder emails, the marketing footer and the marketing unsubscribe page read in the contact's language, with the page language attribute, dates and amounts following it. A Spanish recipient's marketing unsubscribe link carries `lang=es`; without it the page follows that link's own recipient (Spanish when an active contact with the address prefers Spanish), and the page's forms keep the page's language. A typed address is never looked up to choose the language, so the reply never reveals whether an address belongs to a contact. Each firm template (MSG-001) keeps its English text as the version and may carry one Spanish version per template version (the principal or the template's owner adds it; it is immutable, uses the same placeholders and class rules, and a new English version needs a new Spanish one). Bulk preview fingerprints bind each recipient's language and template wording; changes hold dispatch for fresh review, and the existing engagement-opening guard applies to translated wording. Approved ERASURE-002 erasure clears recipient language-review metadata as well as the contact preference, while pending dispatch remains held. Organizer translation metadata exposes only the contact's visible assigned questions and their own submitted originals, including historical labels after a branch hides. Templated requests, portal messages, organizer invitations, bulk messages and invoice reminders use the Spanish version for a Spanish contact. When the template has none, staff are warned before the send at each door: the request, portal-message and organizer-invitation previews warn per contact, a bulk preview lists the untranslated recipients, and the invoice reminder schedule names the template version and the number of Spanish-reading billing contacts on open invoices, at consent and while it runs; the English text is then sent, recorded with the language used. An organizer definition may carry a Spanish question, Spanish choice labels in the same order and a Spanish document request; answers, conditions, workflow bindings and carry always use the recorded (English) choice values. A Spanish signer reads and records the Spanish ESIGN/UETA consent under its own version id (`esign-ueta-v1-es`); the English consent version is refused for her. Text a firm writes (job and template names, request labels, firm-written client status labels, signature field labels, organizer text without a Spanish rendering), the invoice and signature PDFs and certificates, and rare server refusals remain as written or in English. Client flows are held to WCAG 2.2 AA by an automated axe-core scan of the Spanish portal page (with its organizer, signature, upload and shared-login panels) at 1440 and 390 and of the unsubscribe page, with a skip link, labelled controls, a visible keyboard focus indicator and landmark headings. Future client-facing doors (SIGN-001, PAY-001, ENGAGE-001, MAIL-001 to MAIL-003, MOBILE-001, NOTICE-001) inherit the catalog, the contact language and the same scan. Whole-client erasure (ERASURE-002) resets each contact's language preference with the rest of the contact and removes a reminder's recorded language; Spanish template versions are firm records in the firm class, carried by archives under the same restore fence.
