**Implemented native read slice (API-002):** authenticated staff can traverse versioned `/api/blotter/v1/work`, `/api/blotter/v1/time` and `/api/blotter/v1/clients` pages with `{items,nextCursor}` responses.

**Native billing-export read slice (API-002):** GET `/api/blotter/v1/billing/exports` retains native principal/reviewer financial authority and MFA, returning the native export metadata and snapshot string plus explicit snapshot currency (historical currency-less snapshots remain AUD), never CSV bytes. SQL keysets sort descending by preparation instant then id. Optional status is draft, approved or void; from/to are inclusive UTC preparation days. Limits and actor/role/filter-bound cursors follow the native read rules. Reads mutate nothing and restore returns the same historical snapshots. 

**Native client write slice (API-002):** POST `/api/blotter/v1/clients` shares native client validation, contacts, required fields, current principal/reviewer authority and per-session MFA. It requires an `Idempotency-Key` of 1–128 ASCII letters, digits, dots, underscores, colons or hyphens. Each actor email has a separate key space; JSON object key order is immaterial, while array order and exact scalar values matter. A successful write commits its client, contacts, audit and receipt in one transaction. Repeating the same key and payload returns the referenced client as it exists now with `replayed:true`; concurrent repeats create one client and one creation audit. A different payload on a consumed key returns 409; failed validation consumes nothing. The response includes `clientId`, `replayed` and the native client detail fields. If the referenced client has merged away, its normal not-found rule refuses the replay without creating another client. Receipts store only actor email, key/request digests, client reference and time, never request text, credentials or a cached client response. They travel with native archives so restore does not duplicate creation; source sessions and agent keys remain excluded. ERASURE-002 inherits whole-client receipt retention/erasure alongside native client records. Existing native client creation keeps its behavior. 

**Implemented integration boundary (API-002, ct 21 Oct key authority):** Principal-only second-factor step-up mints non-person credentials with explicit client and action grants. Credentials intersect their creator's live principal identity and confirmed factor, recheck actions and client scope atomically, suspend on observed loss and have separate replay spaces. Admission uses a durable rolling 60-request window over 60 seconds. Entity creation accepts only native entity fields and adds only the new client to that key; contacts, relationships and grants remain human-reviewed. Task creation adds only a label to an active client's open job, with no completion or assignment. Document and billing integration reads expose metadata only; billing grants execute no financial action. Thin signed completion notices contain only event, client and work references and time. Registration is principal-approved and excludes earlier completions. Durable claims, live dispatch checks, stable event ids, retained outcomes and explicit reconciliation prevent blind retries. Restoration removes bearer authority, endpoint secrets and destinations and holds unfinished deliveries; fresh registrations do not backfill history. Erasure removes client grants and replay receipts, suspends a final-client key, cancels unfinished notices as record_erased and names external copies. Named public-door proof: `tests/blotter/integration-keys.test.mjs` (lifecycle, task events, rolling limit, erasure and metadata journeys), `tests/blotter/integration-webhooks.test.mjs` (thin signed completion webhook journey) and `tests/blotter/integration-ui.mjs` (`integrationTaskJourney`, 1440 and 390). The complete Zapier journey needs an authorized workspace; broader work mutations, time recording and document-byte integration doors remain open. Existing staff-session billing exports retain their native snapshot response and are not integration billing grants.
