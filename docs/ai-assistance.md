# Staff AI assistance

AI assistance starts off. Configure the optional OpenAI API key through setup, then open Team and safety, AI assistance. The principal records the reference to the firm's provider agreement or attestation covering no training and no retention, approves a request budget, and enables the feature. Changing the provider or model requires a matching fresh approval. Restores turn assistance off. Provider credentials never enter firm archives.

An ordinary API key and `store: false` do not establish zero retention. The principal must confirm the account's approved data controls before enabling real client processing. See [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data). Blotter records the reference; it does not verify the provider's agreement or claim to delete provider copies.

On a job, open AI assistance, choose one portal conversation or uploaded document and the preparation task, confirm the disclosure, then click Process selected source. No page load, upload or source selection calls the provider. Preparers cannot use the notice task. Existing job, client and document custody rules apply to every read and decision. Internal staff discussions, vault contents, other jobs and transcript context never enter the request.

Tax identifiers, SSNs, bank accounts, IBANs and ambiguous long numbers are masked before transmission. The provider receives only the selected text and the preparation instruction. Unsupported, image-only or unreadable files are named and refused. Files exceeding the supported size or text bound are refused rather than truncated or guessed. Original text and the current client, job period and request appear beside the proposals so staff can verify type, client, period and legibility.

Proposals stay unsaved in the page until Save draft. A saved extraction includes its exact source quote and the request's source identifiers. Extracted values cannot be rewritten through acceptance. Summary, reply and proposed copy name can be edited. Accept or reject each proposal separately. Accepting a filename records the name for a later copy; accepting routing separately creates that internal copy in a chosen request on the same job. It never alters the original, moves a file to another client or grants contact visibility. Accepting text never sends it. Staff use the existing message composer for their own send.

The principal configures the document reading-confidence threshold in AI settings. A proposed score below it marks the document draft for manual review; scores at or above it remain proposals for human review. This is an unverified model estimate, never a calibrated probability or an authorization. Every confidence level requires a person to accept rename and routing separately. Client and period folders continue to show the original and every accepted copy.

Notice amounts and deadlines remain proposed and say “verify against the notice.” The response plan is preparation, never legal or tax advice. Accepting it cannot change a deadline, file, post, send or contact an agency. Transcript comparison awaits RESOLVE-001 and INTEGRATE-006. Mailbox context and signed engagement scope await MAIL-001 and ENGAGE-001.

Notice review shows only recorded native taxpayer authorizations, for the practitioner to check the covered form and period. Draft authorizations are not recorded authority. Those records stay in Blotter and are never added to the model input.

Each provider attempt consumes one request under the principal's current approval, including failures. The request and budget reservation commit atomically before dispatch. There are no automatic retries. Calls are bounded to 24,000 selected text characters, 1,200 output tokens and 30 seconds. Exhaustion requires a new principal approval. The selected inexpensive model is `gpt-5-nano`; [model details and pricing](https://developers.openai.com/api/docs/models/gpt-5-nano) describe its summarization and structured output support. Provider token prices and actual charges remain the provider's authority.

One request audit row records who, source identifiers, provider, model, masked input byte count and time. Request history keeps the masked input hash, never input text. Only explicitly saved output enters the draft store. Saved drafts and proposal decisions belong to the derived AI erasure class, including holds, preview, receipt and stale restore fencing. Erasing an individual source file also removes its saved AI drafts. Provider processing appears among observed outside copies with the recorded attestation boundary. Client portal disclosure is available in English and Spanish.

The public-door assertions are in `./tests/blotter/ai.test.mjs`. The desktop and phone journey is `./tests/blotter/ai-ui.mjs`. The separately invoked `./tests/blotter/ai-live.mjs` makes at most three real provider calls on fictitious fixtures, refuses disabled or unconfirmed requests before the edge, prints masked payloads and provider request identifiers, and never saves a draft or sends a message. It requires an injected key and is excluded from ordinary tests and CI.
